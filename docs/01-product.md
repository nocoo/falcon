# 01 · 产品与范围

状态：首版产品契约，用户已授权实现。更新日期：2026-09-25。实现与验证边界见 [05](05-delivery.md)。

## 产品定义

Falcon 是 Jev 的本机代理与决策观察窗口。Agent 通过 Falcon 请求快速、结构化的分类决策；用户通过同一原生应用检查决策输入是否完整、选项是否合理、结果是否符合预期，以及不同来源的调用量、耗时与 token 消耗。

Falcon 不承担模型推理，也不替 Agent 执行动作。Jev 的准确性取决于上下文、问题和模型；Falcon 负责完整转发、忠实展示和明确的不确定性。

## 已明确的要求

- macOS native app，尽量纯 Swift，尽可能小。
- 本机 HTTP 与 MCP 接入；不同来源使用不同内部 key，统一代理上游 Jev。
- 在界面管理上游 key、base API、来源及内部 key。
- 留存最近 7 天经过本服务的请求，能查看输入、问题、选项、结果和用量。
- 大空间回看是核心：按来源与时间查看 define/state/questions、最终决策、返回时间和耗时，支持历史动画回放。
- 高品质原生界面，参考 Showtime、Lyre 的框架、材质与动效；首版包含可用的观察界面。
- 先交付中文设计文档并通过独立 Codex review，再按后续授权实现；主控负责 UI，逻辑可并行，main 原子提交。

## 首版采用的两项取舍

| 取舍 | 当前实现 | 另一方案与影响 |
| --- | --- | --- |
| “缓存 7 天”的语义 | 最近 168 小时请求与响应留存，每次调用仍请求 Jev | 结果复用会改变时效、计费与请求次数，需另定义命中条件、model alias 更新、来源隔离和缓存命中统计 |
| 官方 SDK 与纯 Swift | 运行时用 URLSession 调官方 HTTP API；官方 Python SDK用于开发期协议互操作验证 | 内置 Python + 官方 SDK，可复用客户端逻辑，但增加解释器、依赖、签名、子进程和体积 |

实现采用上述推荐方案：七天历史留存、Swift HTTP 运行时、官方 SDK 开发期互操作。结果复用与内置解释器不在首版范围。选择另一方案时，先修订涉及的契约。官方 SDK 索引当前仅列 Python、JavaScript / TypeScript，不把“未列出 Swift SDK”扩大为永久不存在。

当前默认值：macOS 15+、Apple Silicon 优先发布；英文产品 UI、中文设计文档；关闭主窗口继续在菜单栏运行，明确 Quit 才退出；登录启动默认关闭。发布、签名和公证尚未执行。

## 关键旅程

1. **首次接入**：打开 Falcon → 填上游名称、HTTPS base URL 与 key → 保存 → 创建“Codex / project-a”来源 → 复制一次性显示的内部 key → 复制 HTTP / MCP 配置 → 发送第一条请求 → 决策出现在列表中。
2. **观察一项决策**：从来源或时间筛选定位请求 → 在大工作区同时核对 state、题目定义和结果 → 检查收发时点与耗时 → 标注“已检查 / 值得关注”并记录短评。
3. **发现异常调用**：Usage 中发现某来源请求激增、超时或低置信度 → 点击图表区间 → 跳转同一筛选条件下的请求列表 → 检查具体证据。
4. **管理权限**：为来源轮换或撤销内部 key → 新请求立即按新权限处理 → 历史来源和记录仍可辨认；已转发请求不被描述为“已撤销上游执行”。
5. **维护连接**：编辑上游 base URL 或替换 key → 界面明确显示将使用的目标 → 新请求使用新配置版本；在途请求使用接收时的快照。
6. **回放历史**：选择一条或一段来源/时间范围 → 暂停、播放、拖动和逐事件查看 → 对照原始输入与结果。单条与多来源区间回放的组合是推荐提案，见 [08](08-review-playback.md)；回放不重新发送请求。

## 首版范围

| 能力 | 首版定义 |
| --- | --- |
| 上游配置 | 多个命名 profile，各保存一组 base URL、key 和默认 model；每个来源明确绑定一个 profile；不做负载均衡或自动切换 |
| 本机接入 | `POST /v1/systemone` 与 `POST /mcp`，共用认证和 DecisionService |
| 来源管理 | 新建、重命名、禁用、轮换 key、归档；聚合按稳定 source ID，不信任自报 agent 名称 |
| 决策记录 | 一个 HTTP 推理调用是一条 request，里面可有多题；保存输入与响应、状态、时间、用量、配置版本 |
| Review | 未检查 / 已检查 / 值得关注、可编辑备注；只改变本地标注，不发送给 Jev |
| 回看与回放 | 宽详情、Focus review、输入/定义/结果同时对照，来源时间线、实际阶段时点与只读历史播放；不产生新推理或 usage |
| 查询 | 时间、来源、profile、model、状态、题型、review 状态；正文关键词搜索按需执行 |
| 可视化 | 请求数、题数、token、错误率、p50/p95 耗时、来源占比、Choice 结果与置信度分布 |
| 导出 | 选中请求的 JSON、当前筛选的统计 CSV；明确时间范围与缺失值；用户显式触发 |
| 清理 | 168 小时滚动窗口自动清理；手动清空需应用内确认，不删除配置和凭据 |

首版不包含结果复用、自动执行 Agent 动作、重新发送历史请求、模型推理解释、云同步、远程共享、LAN 服务、全天候独立 daemon、自动故障转移、插件系统和长期历史仓库。历史动画回放属于本地查看，不是再次推理。

## 语义边界

- “来源”表示哪把 key 发起请求；不能证明某个可执行程序或某个人实际持有它。MCP `clientInfo` 和请求 metadata 都是自报。
- “Jev 决策”表示模型返回的判断；不等于 Agent 最终执行的动作。
- `confidence` 是概率分布的集中程度，不能标成准确率。Noul 没有单独 confidence。
- 一次请求可包含多道独立问题；它们共享 state、并行判断，不能读取彼此答案。
- 用量按请求统计，不能为每道题重复计算。失败且上游没返回 usage 时显示“未知”，不能算作零。
- 手工 review 是人的观察标签，不自动变成模型准确率或校准评估。

## 成功标准

新用户完成接入后，无需读原始 JSON 就能回答“谁、何时、什么输入与选项、返回什么”；需要核验时可展开完整原文。10 万条合成记录下仍能顺畅筛选与浏览。界面、协议正确性和资源预算的具体验收见 [05](05-delivery.md)。
