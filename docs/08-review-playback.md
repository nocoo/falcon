# 08 · 大空间回看与动画回放

状态：根据用户强调的核心回看需求补充设计，尚未实现。界面布局见 [04](04-interface.md)，时间字段见 [02](02-architecture.md)。

## 这次明确的体验要求

用户打开 Falcon 后应能清楚检查：不同来源在不同时间送来了什么 define / state / questions，Jev 最后返回了什么，以及何时返回、耗时多少。详情是主要工作区，时间线和动画帮助定位与理解记录。

两处展示细节仍为提案：define 暂以 Definitions（题目指令和候选项定义）呈现，原文若有独立 `define` 则另列原字段；动画回放建议同时提供单条分步查看和跨来源时间段播放。没有把这两处解读当作用户已明确选定的协议定义。

## 信息必须对应原始证据

| 信息 | 呈现与来源 |
| --- | --- |
| 谁 | 来源名称快照、source ID、上游 profile；agent/project/run 标签注明自报 |
| 何时 | 本地接收 UTC、本地化显示，毫秒精度；来源分轨与精确范围定位 |
| State | 完整输入上下文，可展开、查找、复制；默认与题目/结果同时可见 |
| Define / Definitions | instructions、criteria 中的选项/等级及定义，与原文路径对应；未知 define 原样展示，不解释其上游含义 |
| Questions | question ID、题型和指令；同次请求的全部问题均可定位 |
| Decision | Jev 实际返回的选项/yes 概率/score、完整分布、适用的 confidence；失败或未知独立显示 |
| 时间 | 本地准备、上游往返、代理处理、返回完成；缺失阶段为空，不补零 |

Jev 非流式返回一次结果。不存在已知的逐题开始/结束时间、推理链或选项逐步淘汰轨迹；画面不能制造这些信息。概率条在结果实际可用时一起出现，不让概率从零逐渐上涨来冒充模型计算。

## 单条回放

进入单条 Replay 后保留同一个宽详情布局，增加底部时间尺、播放/暂停、逐事件前进/后退、0.5× / 1× / 2× / 4×、拖动定位和 `Show final result`。默认暂停，从用户选定位置开始；可以随时退出到静态完整结果。

事件只有：**收到请求 → 发出上游 → 收完整响应 → 处理结束 → 本地返回完成**，只呈现已记录的时点。state / definitions / questions 在收到请求时作为同一份输入可见；可以用焦点逐段引导阅读，但明确属于“阅读步骤”，没有分别发生的请求事件时间。上游等待区显示实测时长；不知道何时收到响应就没有结果揭示事件。

批量多题共享同一响应时点，答案同时可用，用户随后逐题阅读。上游 4xx/5xx 显示错误响应到达，不显示成功 Decision；timeout / interrupted 在已知终止点显示失败或未知，缺少时点时用缺失标记，禁止补造结束时间。返回完成未知时不画成功送达标记。

拖回响应前，Replay 的结果区显示“结果在此时尚未返回”；时间游标明确标识“历史播放时点”。`Show final result` 切回静态完整记录，不改变留存或统计。结果展示过渡建议 160 ms 淡入，时间游标匀速，不使用装饰粒子、虚构加载百分比或推理节点。

## 多来源区间回放

从时间/来源筛选创建本次播放范围，默认按历史时间升序；来源轨道和选中请求详情联动。保留并发关系：请求 A 等待期间，来源 B 的请求可以出现和完成。共享响应时点的多题不能依次占用一段串行时间。

播放头按同一历史时间轴推进，来源轨道上的进行中请求保留状态。详情只显示当前选中的一条，背景请求到达不抢走阅读焦点；可显式打开 `Follow arrivals` 按接收事件跟随。相同时点按 received_at、request ID 排序稳定显示，不据此推断先后因果。选择新的请求会暂停跟随，保留时间游标。

播放开始时冻结筛选与候选记录集合；只纳入当时已完成或已恢复为 interrupted 的记录，正在发生的新请求留在 Live 中，不插入正在看的历史。最多选取 10,000 条，超过时要求缩小范围，不能静默截断。清单只持有 ID 和轻量时点，短 read transaction 后释放；正文只读当前选中记录，相邻项仅预读摘要。后续改动的 review 备注不改变播放的原始决策事件。

默认按实际时间差与选定倍速播放。提供显式 `Skip idle gaps`，只跳过没有在途请求、没有事件的空档，游标标出“跳过 12m 08s”；不得跳过一条请求的上游等待区而仍显示为原速。也可逐事件前进，始终保留原始时长数值。改变筛选时暂停并重建播放范围，不悄悄跳到另一组请求。

墙钟变化可能使不同请求的绝对时间顺序失真；同请求阶段按持久化单调 offset 还原。检测到墙钟跳变的记录带标识；跨该边界不宣称真实全局因果顺序，可使用逐请求查看。不通过动画平滑掉记录中的时间异常。

## 回放生命周期与七天边界

- Replay 是只读本地查看，绝不调用 Jev、不发送 MCP tools/call、不创建新推理请求、不增加 usage、不自动改 review 标签。服务 Pause、来源撤销或上游不可达不影响尚未到期的历史阅读。
- 回放范围的“历史时间”只控制画面；留存始终使用当前真实时钟。过去的游标不得复活已到期记录。
- 播放或暂停期间某条记录到期：立即从可见正文和内存缓存撤下，播放清单移除该项；当前项到期则暂停并提示，允许手动跳到下一条有效记录。清空历史会立即停止播放并清空清单与正文。
- 新建播放器不复制整份历史，不产生可绕开清理的永久 replay 文件；应用重启只恢复普通布局偏好，不恢复正文缓存或已过期播放队列。
- 数据读取或正文解析失败时暂停在该条并显示实际错误，不跳过后继续伪装为完整回放。
- 离开回放页、关窗或应用进入非活动状态时暂停计时；重新进入仍暂停，不在不可见状态持续渲染或补播大量动画。服务端继续接收新请求。
- Reduce Motion 关闭移动和淡入效果，保留逐事件、播放/暂停与静态游标更新；VoiceOver 可朗读事件清单，默认不逐帧朗读时间。

## 实现与验收

使用原生 SwiftUI 和轻量 `ReplayViewModel`：纯函数根据记录、游标得到可见状态，播放时钟可注入测试。不引入视频引擎、WebView、事件溯源平台或单独数据库；持久化仍是一条 request 的少量时点加原始 JSON。动画只更新可见游标与发生变化的状态。

核心验收：

1. 在 1600×1000 / 全屏下同时核对完整 state、当前题指令/定义和返回结果；1120×720 下 Focus review 可访问全部内容，长文本不会因省略号而无法核验。
2. 合成数据包含两个来源、交错请求和同一批次三题；按时间、来源查找能定位同一原文，回放保持真实并发和统一响应时点。
3. 播放、暂停、倍速、拖动、倒退、逐事件和跳过空档只影响展示；测试拦截全部出站调用，计数必须为零，usage/review 数据不变。
4. 注入可控时钟验证 timing 差值、未知阶段、超时、返回失败、墙钟跳变；不能显示模型推理耗时或 Agent 已消费结果。
5. 播放中和暂停中跨过 168 小时、清空历史、读取失败、切换来源、退出窗口，均符合上述生命周期；不保留过期正文。
6. 10,000 条轻量清单、长 state、255 选项下保持有界内存与流畅拖动；可见动画目标 60 Hz，不触发整库解码。实际资源预算沿用 [05](05-delivery.md)，未实测不宣称达标。
